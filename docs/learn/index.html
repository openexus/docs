Introduction

Welcome to Openexus!

Openexus is as unified platform for building Modules and Applications with simplicity and ease. With just a few clicks or some simple AI description, the application of your dreams is ready to be explored and shared. The only thing it takes is imagination.

Today, digital creations are made up of monolithic applications with thousands of lines code; hunderdeds of thousands of lines of code even. We believe that with a well designed building blocks concept we can design a world where creations are simple to build using with highly reusable blocks. These blocks can span multiple languages and frameworks and remove all the complex and esorteric programming concepts that get in the way.

The Open Module Specification​

The core aspect of Openexus is the Module. A Module is functionally just a building block of some aspect of a software system. By creating and combining Modules together, either your own or those of others, we can build larger and more complex systems.

Think of Open Module as a smart Lego block for digital creations. Just like Legos...

  • Modules can snap (aka connect) with other Modules.
  • Each Module can have different features (different properties).
  • Connecting multiple Modules together will form a more complex and interesting creation.

At the heart of a Module, is what we call the Open Module Specification.

Features​

The Open Module Specification is designed with these principles in mind:

  • Simple to use by non-coders;
  • Programming language agnostic;
  • Built to be highly reusable;
  • Designed to be understood by AI.

Core Concepts​

There are a few Core Concepts one should know to get going with Openexus. These are

  • Modules;
  • Instances;
  • Properties;
  • and Connections.

We describe each of these below.

Modules​

The primary building block of Openexus is the Module. A module is a building block (like Lego blocks) that allow users to piece them together to create interactive pages or applications. A Module can be as simple as a single function (e.g. age calculator) or as complex as an entire entity with complex visual and interactive elements (e.g. a map component).

More fundamentally though, a Module is the description of a building block, the blueprint of it. It describes the module itself (the Manifest), the means of communication with the Module (the Properties), and the logic that is performed when the module is used or changes in some way (the Logic).

We will go more into each of these concept in a minute.

Instances​

An Instance is a running copy of a Module. If a Module is blueprint, an instance is a single implementation of that blueprint. If you think of a Module as a blueprint of a house, an Instance is the actual built house, a single stamped output of taking a blueprint and implementing against it.

When you add a Module to an Openexus application, you are creating an Instance of that Module. Changes you make to that Instance are only applicable for that Instance and do not change the module itself.

It is an important distinction to understand, the difference between a Module and an Instance.

Properties​

Each module defines zero or more Properties. A Property is a single named data point of a Module. These data points each hold a specific value. The type of the value and what its is is entirely dependent on the Module being used.

Connections​

Instances are tied to one another by a Connection. A Connection represents a binding between two specific Properties in two separate modules. You connect a Property on some Module to a Property on a different Module.

When a Property changes on the first Module, the Property on the second Module is changed as well. We describe this as the Properties being "in-sync" meaning that what happens to one is reflected in the other.
