The Context Object

Before we talk about the Context Object, a quick review of what Modules and Instances are is in order. A Module is the definition and all the bits necessary for the Module to be executed. An instance is a single execution of a Module. For example, if one has an Input Module and ran it two separate times, they would have two separate Instances, one for each execution. When we are writing a Module, the context object that we often work with, is the running instance. So in our prior example of two Input Instances, each has its own context.

Using the ContextObject​

The Context Object is available in your code as the context variable. All of the members and methods described below are executed from the context object. For example, if we wanted to get a property value of the currently executing instance we would do so by calling `context.get().

ContextObject Methods​

use(...args: unknown[]) => unknown

Used for frameworks to obtain a reactive pass through to instance properties. For example., if you are working with a framework like React, you might use it to get a getter/setter for a property. The getter/setter is a react store and behaves as expected of a react store.

trigger(propertyKey: string, event: unknown) => void

Used to fire a Trigger event for the given propertyKey. The event object passed to this function will be provided as the event argument to down-stream trigger receivers.

run(propertyKey: string, ...args: unknown[]) => void

Used to execute an Action for the given propertyKey. Any additional arguments passed to the run function will be passed to the Action execution.

get(propertyKey: string) => unknown

Returns the current value of the given propertyKey.

set(propertyKey: string, value: unknown) => void

Sets the current value of the given propertyKey to value. Subscriptions, effects, and related signals bound to propertyKey will trigger after this value is updated.

update(propertyKey: string, updateFunction: Function) => void

Updates the current value of the given propertyKeys based on the return result of the updateFunction function. The updateFunction function has the following signature:

<updateFunction> = (oldValue) => newValue

mutate(propertyKey: string, mutator: Function) => void

Updates the current value of the given propertyKeys based on the return result of the mutateFunction function. The mutateFunction function has the following signature:

<mutateFunction> = (oldValue) => newValue

subscribe(propertyKey: string | string[], handler: Function) => void

Subscribe to notification when the given propertyKey (or propertyKeys) is changed. The handler is executed any time the propertyKey (or set of propertyKeys) changes. The handler function has the following signature:

An alternate version of subscribe is allowed where one provides * as the property key, in which case all properties are subscribed.

<handler function> = (newValue: unknown, oldValue: unknown, propertyKey: string) => void

unsubscribe(propertyKey: string | string[], handler?: Function) => void

Unsubscribe from notification when a property changes. One may specify a specific propertyKey or an array of propertyKeys to unsubscribe from. Unsubscribe will only occur on notifications that specifically match the given handler. Because functions are passed by reference in JavaScript/TypseScript this must be a referential match and not a content match.

An alternate version of unsubscribe is allowed where one provides * as the property key, in which case all subscriptions that match the given handler function will be unsubscribed.

notify(state:string, reason: string) => void

Used to visually notify an instance that it is in a given state for a given reason. The possible state values are given below. If an invalid state is given, the notification WILL NOT be displayed.

Possible states are:

  • error
  • warning
  • success
  • info
  • fetching
  • fetched
  • loading
  • loaded

context.render(renderFn: () => HTMLElement) => (el: HTMLElement) => void

Used with modules that have to render some output. context.render() takes as its sole argument a function that when called returns a HTMLElement object. This HTMLElement is then appended DOM as the output of the module.
