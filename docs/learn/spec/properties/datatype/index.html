datatype

The datatype Property field provides a hint to Openexus and users as to what kind of thing a Property can hold. This in turn steers what a Property can connect to and interact with. datatypes are useful indicators on how properties can communicate with other properties.

Here's just a small example smattering of datatype usage...

properties.yaml
ui:
  datatype: web-view
slot:
  datatype: 'web-view[]'
some_datatype_I_have:  
  datatype: text
some_action:
  datatype: action
  properties:
    - key: id
      datatype: text
some_trigger:
  datatype: trigger
your_secret:
  datatype: secret

Types​

Primitive datatypes​

Standard primitive datatypes are simple, fundamental structures.

text - Holds text like "Openexus is great!". This is sometimes called a "string" in other programming languages and systems.

boolean - A type that can be either true or false, nothing else.

number - Holds a number value, be it a whole numer or a real number.

Dates​

Support for working with Dates and Times. Please also see

js-date - Holds the date in a JavaScript Date() object.

Compound datatypes​

Compound types are types that are a compond of other types. Examples include arrays, object, json, maps, dictionaries, and lists.

[_type_] - Array of a certain type (remember to replace _type_ with one of the primitives) For example: [boolean] which can hold values like: [ true , false , true ]

json - Holds a JavaScript object For example: json => { a : 1, b : 2 }.

json-text - Holds a JavaScript object in string format => "{a:1,b:2}".

option - Holds a list of options you specify. You have to list the options with the datatype as well.

For example:

position:  
  datatype:
    type: option
    options:
      - top
      - bottom

UI & Slot datatypes​

Specific to the rendering of a Module, these types indicates that the Property will have a function that will return HTML.

html - Holds the rendered output of a Module. This means when used, the HTML of the Module will be returned for that Module.

'web-view[]' - Holds a slot input into a Module, which is an array of html. Usually used to join up other html types together into a layout.

Trigger datatype​

trigger - A trigger datatype is a special type that is used to notify of some event on a Module. When an event is fired or emitted from the Module, any connection to the associated trigger will be notified. For example, a button Module may have a on_click property with datatype: trigger.

trigger properties can only connect to action properties.

Action datatype​

action - An action datatype is a special type that is used to execute or run some behavior of the Module. When an action receives notification from a trigger, the associated behavior is executed. For example, on_click (trigger) can be connected to a send_email (action). It may be helpful to think of an action as a function or block of code that can execute when a trigger connected to it has an event.

action properties can only connect to trigger properties.

Any datatype​

The any datatype means that a Property can accept connections from any other datatype. Largely, one should avoid using any as a datatype as it will make connections harder to use.

Extended datatypes​

Extended datatypes are datatypes which derive themselves from a more common parent type, such as the types above. As such, they can connect to properties with the parent type in addition to those of the same type. For example, a email type can connect to another email type or to it's parent type of text.

Note: Some Extended datatypes may be validated to make sure they conform to their specific type needs and setting a value on these properties may throw errors if they fail validation. For example, an email type is validated to ensure that it meets Email Address formatting.

Extends text​

The following types all extend the text datatype and thus can connect to properties of the same type or properties of type text. For example, a email type can connect to another email type or to it's parent type of text.

Extends text (Identity)​

email - Holds an email in plain text. Validated to check if it is in email format (has an @ sign).

name - Holds a person's full name in plain text.

first-name - Holds a person's first name in plain text.

last-name - Holds a person's last name in plain text.

username - Holds a username in plain text.

password - Holds a password in plain text.

Extends text (Secrets)​

secret - Holds a reference to a secret value that cannot be displayed, only used. Usually for API keys or holding sensitive passwords. A secret type is intentionally obscured from users and developers to protect their contents and avoid exposing this information. The secret is only fetched when it is needed in a module. For more information about Secrets, please read the Using Secrets section.

Extends text (Currency)​

currency - Holds a number and a currency.

currency-alpha - Holds the currency in plain text as a 3 letter currency code (ISO 4217). For example: USD, EUR, JPY

cc-number - Holds a Credit Card number in plain text. Validated to check that the value matches known Credit Card Number standards. Same as credit-card-number below.

credit-card-number - Holds a Credit Card number in plain text. Validated to check that the value matches known Credit Card Number standards. Same as cc-number above.

Extends text (Technical)​

url - Holds a URL in plain text. Validated to check if it is in URL format (starts with http:// or https://).

uuid - Holds a Universally Unique Identifier in plain text. Validated to check if it is in uuid format (36 alphanumeric with dashes).

ip - Holds an Internet Protocol address in plain text. This may be either an IPv4 or IPv6 address. Validated to check if it is in an IPv4 or IPv6 address format.

ipv4 - Holds an Internet Protocol address in plain text. This must be an IPv4 address. Validated to check if it is in an IPv4 address format.

ipv6 - Holds an Internet Protocol address in plain text. This must be an IPv6 address. Validated to check if it is in an IPv6 address format.

sql-statement - Holds an sql statement in plain text.

jmes-path - Holds a jmes-path in plain text.

css-stylesheet - Holds a css-stylesheet in plain text.

css-unit - Holds a css-unit in plain text. For example: 12px, 1rem, 2em, etc

Extends text (Colors)​

css-color - Holds a css color in plain text. These may be of any supported CSS color expression form. Please see MDN <color> value documenation for more details.

color-css - Holds a password in plain text. These may be of any supported CSS color expression form. Please see MDN <color> value documenation for more details.

color-hex - Holds a color represented as a hexadecimal string.

color-rgb - Holds an color represented as a RGB string of three decimal octets.

Extends text (Location)​

location - Holds a latitude and a longitude pair. In the format of ISO 6709 (/ is terminating, no comma). For example: "+48.8577+002.295/"

country - Holds a country name in full. For example: "United States of America"

country-alpha-2 - Holds a two letter country code in plain text. For example: US, CN, IN

country-alpha-3 - Holds a two letter country code. For example: USA, CHN, IND

timezone - Holds the timezone specified in a string.

Extends text (Date and Time)​

datetime - Holds the Date and Time in plain text. In the format of ISO 8601: YYYY-MM-DDThh:mm:ssZ (UTC).

date - Holds a Date in plain text. In the format of ISO 8601: YYYY-MM-DD.

time - Holds a Time in plain text. In the format of ISO 8601: hh:mm:ss.

timezone - Holds the timezone specified in a string. In the format of ISO-8601 Time Zone. For example: +04:00

year-week - Holds a date in plain text with the year and week. In the format of ISO 8601: YYYY-Wxx. For example: 2024-W18

year-week-day - Holds a date in plain text with the year, week and day. ISO 8601: YYYY-W1xx-x. For example: 2024-W18-4

year-ordinal-date - Holds a date in plain text with the year, ordinal and day. ISO 8601: YYYY-ddd. For example: 2024-123

year-month - Holds a date in plain text with the year and month. In the format of ISO 8601: YYYY-MM.

Extends number​

The following types all extend the number datatype and thus can connect to properties of the same type or properties of type number.

Extends number (Currency)​

currency-numeric - Holds the currency as a 3 digit number currency code (ISO 4217). For example: 840, 978, 392

Extends number (Location)​

country-code-numeric - Holds a number referring to a country. E.g 840, 156, 356

zipcode-us - Holds a US zipcode in as a number. For example: 94043

Extends number (Date and Time)​

datetime-epoch - Holds the datetime (Unix Epoch/POSIX time) in plain text as a number. For example: 1618921342

Other datatypes​

The following additional datatypes are also supported.

pointer-event - Holds the pointer event of a mouse/touch event.

data - Holds general data from an API response.

image - Holds an image in the form of a blob string.

file - Holds a file in the form of a blob or URL reference.

Default Type​

If no datatype is specified for a Property, the default type of any is used. As we mention above, it is undesirable to use the any type, so please avoid not providing a datatype for properties.

Datatypes & Connections​

Datatypes provide a useful hint as to how Modules can communicate with each other, similar to typing in a programming language. Some common rules are:

  • any can always connect with any other Property, irregardless of datatype.
  • trigger datatypes can only be connected with action datatypes.

Platforms that implement the spec can decide how to treat connections with different datatypes. On openexus, when different datatypes are connected (For example: number to text), we will provide a warning to the user and also try our best to cast the datatypes accordingly.
